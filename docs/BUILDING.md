# Building Light2Life with EAS

App ID (iOS bundle identifier and Android package): `com.turnonac.light2life`.
Do not change it again once the app is on the App Store or Google Play: both stores tie the
listing to it for good. Expo project: `@turnonac/light2life`.
(The first TestFlight builds used `com.turnonac.walkinlight` and the Expo project
`@turnonac/walkinlight`; both are retired.)

Build profiles live in `eas.json`:

| Profile | Use |
| --- | --- |
| `development` | Dev client (internal) |
| `development-simulator` | Dev client for the iOS Simulator |
| `preview` | Internal test builds; Android builds an APK |
| `production` | Store builds: Android AAB, iOS App Store; build number auto-incremented |
| `screenshots` | `preview` plus `EXPO_PUBLIC_SCREENSHOT_MODE=1` (privacy cover off). Never submit it |

`cli.appVersionSource` is `remote`: EAS stores the iOS build number and Android version code,
and `production` increments them. The user-facing version is `version` in `app.json`.

## Credentials

Signing credentials and store keys live on EAS servers, not in this repo or the environment:

| Credential | Where | Notes |
| --- | --- | --- |
| Android upload keystore | EAS | Generated by the first Android build |
| Google Play service account key (JSON) | EAS | Uploaded once by the owner; used by `eas submit -p android`. No key path in `eas.json` |
| iOS distribution certificate + App Store provisioning profile | EAS | Team QT95N5YJ49 (Individual); expire 30 Oct 2027 |
| App Store Connect API key for submissions (Admin) | EAS | Used by `eas submit`, and by non-interactive builds to check or repair the provisioning profile |
| App Store Connect app | `eas.json` `submit.production.ios.ascAppId` | Light2Life, bundle ID above |

The only environment variable builds need is `EXPO_TOKEN` (Expo personal access token, never
committed). Run `npm ci` first: EAS reads `app.json` plugins from `node_modules`.
Never commit keystores, service account keys or `.env` files (`.gitignore` covers the usual names).

## iOS release

```sh
npx eas-cli@latest build -p ios --profile production --non-interactive    # iOS store build
npx eas-cli@latest submit -p ios --latest --non-interactive               # upload to TestFlight
```

Apple then processes the build (5–30 minutes) before it appears in TestFlight. App Store review
also needs a privacy policy URL (see [Privacy policy](#privacy-policy)).

## Android release

```sh
npx eas-cli@latest build -p android --profile preview --non-interactive      # test APK
npx eas-cli@latest build -p android --profile production --non-interactive   # Play Store AAB
npx eas-cli@latest submit -p android --latest --non-interactive              # upload to Google Play
```

`submit.production.android.track` in `eas.json` is `internal`, so uploads go to the internal
testing track. `--latest` takes the newest Android build of any profile: submit right after the
production build, or pass `--id <build id>`. Never submit a `preview` or `screenshots` build.

One-time setup (owner):

1. Create the app in Google Play Console with package `com.turnonac.light2life`.
2. Create a Google service account key with access to the Play Console account
   (https://expo.fyi/creating-google-service-account) and upload the JSON to EAS: EAS dashboard ›
   Credentials › Android › `com.turnonac.light2life` › Service credentials, or
   `npx eas-cli@latest credentials -p android` › Google Service Account. Non-interactive
   submits fail until a key is assigned. Keep the JSON file out of the repo.
3. Complete the store listing and the app setup tasks in Play Console. The app stays in draft
   until they are done.

New personal Play developer accounts (created after 13 November 2023) must run a closed test
with at least 12 testers, opted in continuously for 14 days, before they can apply for
production access. Promote a release from internal testing to the closed test in Play Console.

## Store screenshots

Normal Android builds block screenshots (FLAG_SECURE, the app-switcher privacy cover), so store
screenshots come out black. Use the `screenshots` profile, which turns the cover off:

```sh
npx eas-cli@latest build -p android --profile screenshots --non-interactive
```

Install the APK on a test device, take the screenshots, then uninstall it. Never submit this
build or use the profile for store builds, and do not set `EXPO_PUBLIC_SCREENSHOT_MODE`
anywhere else (for example a local `.env`). iOS does not need it: the iOS cover only blurs the
app in the app switcher.

## Privacy policy

Both stores need a privacy policy URL before release.

1. Publish the privacy policy page at a stable public URL.
2. Set `PRIVACY_POLICY_URL` in `src/app/(tabs)/settings/about.tsx`. The "Privacy policy" row in
   About appears once it is not empty. Ship it in the next store build.
3. Enter the same URL in App Store Connect (App Privacy) and in Play Console (App content ›
   Privacy policy).

## Renewing or recreating iOS credentials

Non-interactive builds can reuse iOS credentials but cannot create a distribution certificate.
When it expires (30 Oct 2027) or is revoked, run this on a machine where you can sign in to your
Apple ID with two-factor authentication:

```sh
npx eas-cli@latest credentials -p ios    # profile: production
```

Choose to generate a new distribution certificate and provisioning profile. To replace the
submit key, use the App Store Connect API key option and let EAS generate a new key.
