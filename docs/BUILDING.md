# Building Light2Life with EAS

App ID (iOS bundle identifier and Android package): `com.turnonac.walkinlight`.
The store name is Light2Life; the bundle ID, Expo slug (`@turnonac/walkinlight`) and URL
scheme keep the original WalkInLight name and must not change.
Build profiles live in `eas.json`: `development` (dev client), `development-simulator`,
`preview` (internal; Android APK), `production` (store builds, auto-incremented).

## Credentials

Signing credentials and the App Store Connect API key live on EAS servers, not in this repo
or the environment:

| Credential | Where | Notes |
| --- | --- | --- |
| Android upload keystore | EAS | Generated by the first Android build |
| iOS distribution certificate + App Store provisioning profile | EAS | Team QT95N5YJ49 (Individual); expire 30 Oct 2027 |
| App Store Connect API key "[Expo] EAS Submit …" (Admin) | EAS | Used by `eas submit`, and by non-interactive builds to check or repair the provisioning profile |
| App Store Connect app | `eas.json` `submit.production.ios.ascAppId` | `6828680079` (Light2Life) |

The only environment variable builds need is `EXPO_TOKEN` (Expo personal access token, never
committed). Run `npm ci` first: EAS reads `app.json` plugins from `node_modules`.

## Routine release

```sh
npx eas-cli@latest build -p android --profile preview --non-interactive   # Android test APK
npx eas-cli@latest build -p ios --profile production --non-interactive    # iOS store build
npx eas-cli@latest submit -p ios --latest --non-interactive               # upload to TestFlight
```

Apple then processes the build (5–30 minutes) before it appears in TestFlight. App Store review
also needs a privacy policy URL, both in App Store Connect and in `PRIVACY_POLICY_URL`
(`src/app/(tabs)/settings/about.tsx`).

Free tier: 15 iOS + 15 Android builds a month, low-priority queue (expect 15–30 minutes).
Google Play publishing needs the Play developer account and a 12-tester, 14-day closed test first.

## Renewing or recreating iOS credentials

Non-interactive builds can reuse iOS credentials but cannot create a distribution certificate.
When it expires (30 Oct 2027) or is revoked, run this on a machine where you can sign in to your
Apple ID with two-factor authentication:

```sh
npx eas-cli@latest credentials -p ios    # profile: production
```

Choose to generate a new distribution certificate and provisioning profile. To replace the
submit key, use the App Store Connect API key option and let EAS generate a new key.
